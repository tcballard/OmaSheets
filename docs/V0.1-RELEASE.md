# v0.1.0 native release gate

**Status:** engineering in progress; no release is authorised.

v0.1.0 is the first public native-document alpha described by M2 in the
roadmap. It does not replace the v0.0.2 LibreOfficeKit compatibility path.
Compatibility workbooks and native `.omasheets` documents remain visibly
different products inside one application until the native round-trip surface
earns broader claims.

## Release promise

A v0.1.0 user can create or import a bounded native document, edit it through
the authenticated local service and native grid, recover the exact state by
deterministic replay, work on a branch with checks and semantic diff, approve a
gated merge locally, and export their data through documented no-clobber
projections. Agents cannot append to `main`, approve a merge or publish output.

## Engineering checklist

| Capability | Current evidence | Ship gate |
| --- | --- | --- |

| Branches, checks, semantic diff and gated merge | Store and service tests | Same workflow exercised through the shipping UI/API |
| Structured references, computed columns and inferred types | Core/calc/service tests | Retained in the installed-product suite |

| Native import | Bounded XLSX conversion stages one event transaction, publishes without replacement and verifies replay digest | Installed API proof plus dogfood workbook review confirms the manifest is sufficient |
| Omarchy integration | Reproducible bundle includes the native service and installs user-facing `omasheets` and `omasheets-service` commands; compiler-free acceptance exercises import, edit, branch, check, diff, merge, CSV, close and reopen | Grid binary, native file association and rollback pass the same installed workflow after owner review |

## Required release evidence

1. Fill the decision block in `docs/M0-REVIEW.md` with the baseline hardware,
   cold/warm state and exact benchmark output.
2. Complete `docs/M1-GRID-SPIKE.md` on Omarchy with keyboard, screen-reader,
   theme, scroll, paint-latency and idle-memory evidence.
3. Record one recurring native dogfood workload and prove its final digest is
   identical after closing, reopening and replaying from the event log.
4. Exercise create/import, edit, branch, check, diff, merge and every export
   through the same installed API used by the UI.
5. Build the compiler-free Arch bundle from the exact tagged source, verify its
   provenance and signature, install it through the production Omarchy path,
   and remove it cleanly.
6. Run the frozen corpus scorer alone on the declared runner. Corpus evidence
   remains aggregate; no workbook path, cell content or per-file result enters
   the release record.
7. Obtain explicit maintainer approval before merging the release stack,
   tagging v0.1.0, publishing binaries or changing marketplace state.

## Explicit non-claims

- No perfect Microsoft Excel compatibility.
- No VBA, add-in or external-workbook execution.
- No volatile clock or random functions without explicit ticks.
- No silent formula, style, table, lineage or check preservation through a
  format that cannot represent it.
- No performance statement derived from headless CI or overlapping benchmark
  runs.
